## 🔄 Workflow for New Tests

### When Adding New Test Report
1. Run test through `run_tests_sequential.py`
2. Reports automatically save to `reports/` with timestamp
3. Update `TEST_EXECUTION_REPORT_20260804.md` with new results
4. Add any screenshots to `screenshots/` folder
5. Document any issues in `issues/` folder
6. Update `README.md` status tables

### When Documenting Issues
1. Create markdown file in `issues/` folder
2. Include detailed analysis and root cause
3. Add screenshot to `screenshots/` folder
4. Reference screenshot in issue document
5. Include reproduction steps
6. List recommendations

### When Sharing Reports
1. Use `TEST_EXECUTION_REPORT_20260804.md` as main document
2. Include screenshots from `screenshots/` folder
3. Reference detailed issues from `issues/` folder
4. Attach relevant HTML test reports
5. Include summary from `test_summary_*.txt`

## 📅 Timestamping Convention

All reports and files use timestamp format: `YYYYMMDD_HHMMSS`

Example: `test_login_20260804_141936.html`
- Year: 2026
- Month: 08
- Day: 04
- Hour: 14
- Minute: 19
- Second: 36

This allows:
- Easy sorting chronologically
- Tracking multiple test runs
- Historical comparison
- Audit trail

---

## 🎨 Screenshots Naming Convention

Screenshots follow pattern: `{module}_{issue_type}_{severity}.png`

Example: `plan_creation_restriction_error.png`
- Module: plan_creation
- Issue Type: restriction
- Severity: error

This helps:
- Quickly identify what screenshot contains
- Organize multiple screenshots
- Track issue types
- Easy searching

## 🔒 Data Retention

- HTML test reports: Keep for 30 days
- Screenshots: Keep indefinitely (for reference)
- Issue reports: Keep until resolved
- Markdown reports: Archive after sprint ends
- Summary files: Keep current + previous 5 runs
